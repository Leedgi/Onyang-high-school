# 실제 촬영 사진 OCR 검사 · 2026-10-31

사용자가 제공한 14개 제품 42장을 모두 사용했다. 최상위 JPG 12장은 `samples/ocr/`로 옮겼으며 사진 바이트는 바꾸지 않았다. 다른 사람이 추가한 최신 UI·설명 패널은 보존했다.

정면 14장 중 정밀도와 재현율 모두 80% 이상은 **14/14장**, 90% 이상은 **9/14장**이다. 정면 사진 최저 정밀도 86.7%, 최저 재현율 80.8%이다.
42장 전체의 사진별 평균 정밀도/재현율은 기존 **32.7%/30.2%** → 개선 **81.3%/79.5%**다. 두 지표 모두 80% 이상은 **32/42장**이다.

정밀도 = 읽은 서로 다른 성분명 중 맞은 비율, 재현율 = 실제 정답 성분명 중 찾은 비율이다. 이름의 한 글자가 틀려도 DB의 정확 별칭 또는 실제 정답과 일치하지 않으면 오답이다. 유사도 점수를 맞힌 수로 사용하지 않는다. 아래 기본 수치는 **사용자 확인 전 제안 목록**이며 원문 성적도 JSON에 별도로 기록했다. 원문·수정 기록은 보존하고 성분 숫자나 nano를 삭제해 점수를 높이지 않는다.

이 42장은 개선에 사용한 개발 세트다. 처음 보는 제품 전체에서 같은 정확도를 보장하지 않는다. 흐림·반사·가려짐·곡면 가장자리의 눌린 글자는 여전히 틀릴 수 있다. 목표에 못 미친 사진도 표에서 제외하지 않았다.

## 변경과 연결 규격

| 입력 | 처리 | 출력 | 실패 |
| --- | --- | --- | --- |
| 사진 bytes·파일명 | EXIF, 네 방향, 약할 때 높은 해상도 재검사, 원근·윤곽 곡면·겹침 검증 줄 비교 | 기존 ScanOutput/IngredientScan v1, 미확정 성분 초안 | 파일 ValueError 또는 기존 OCR 오류 상태·직접 입력/재시도 |
| 줄/성분 원문 | 줄바꿈·구분자·함량 주석을 보존하며 이름 대조, 숫자가 같은 제한된 철자 제안 | 원문과 변환 기록, confirmed=False | 동점·숫자 차이는 임의 확정하지 않음 |
| 명세와 각 사진 | 실제 모델 추론 후 정답 TXT와 정확 별칭만 비교 | 사진별 P/R/F1·누락·오답·시간 JSON | 사진 SHA 불일치·모델 실패를 보고 |

기본 엔진은 공식 PP-OCRv5 한국어 ONNX CPU이며 모델 배포 커밋과 SHA-256을 고정했다. 사진은 외부 AI로 보내지 않는다. 요청 안에서만 문자열 대조를 재사용하고 요청 종료·실패 후 지워 세션 사이에 원문을 공유 캐시하지 않는다. A recognize_photo/prepare_review, B analyze_confirmed 및 C 최종 확인 한 번 흐름은 유지한다. 함량 단위 주석은 이름 검색에서만 분리하며 실제 배합 함량을 확정하지 않는다.

## 검사 환경

- Linux Python 3.14.8 CPU에서 실제 42장 전후 검사, 전체 pytest 92개, 서버 HTTP, 실제 모델 인공 라벨·회전/곡면 5종 검사를 수행했다. 인공 5종은 각각 26/26개를 읽었으며 촬영 사진 성적과 구분한다.
- [Windows 실행](https://github.com/Leedgi/Onyang-high-school/actions/runs/41167089541): Windows x64 Python 3.14.10 CPU에서 setup, 3.12 환경 보존/전환, 모델 재시도, 전체92개 검사, 서버와 인공5종을 통과했다. 실제42장도 모두 실행했고 사진별 성적이 Linux와 같았다. 39장 목록 반환/3장 영역 미탐지이며, 미탐지를 감지한 전체 벤치마크는 종료코드1로 실패 표시된다. 설치·회귀검사 실패와 구별한다. 사용자 개인 PC 실행 성공을 대신 보장하지 않는다.
- Windows 실제42장의 제안명 정밀도/재현율과 시간은 JSON의 windows에 있다. Linux 시간은 기존 4개/개선 2개 작업 및 다른 검사가 병행되어 통제된 속도 비교가 아니다.
- 정답 TXT는 사진을 직접 대조해 전사했다. 같은 제품 세 각도에 같은 목록을 사용한다. 초록색 상자의 ‘갈바늄수지오일’ 전사 오타는 원본 확대 확인 후 수정했다. 정답·해시는 검사기에만 전달하며 OCR 엔진은 읽지 않는다.

추가 각도(-30/+30/+45/-45°) 및 검출 해상도3200/4000 실험도 실패한 세 사진에서 수행했다. 목표를 만족하는 복구에는 이르지 못했다. 흐림·반사·강한 원근이 있는 이 사진에서는 직접 수정/재촬영 경로가 필요하다. 실험 입력의 결과는 위 앱 파이프라인 성적과 구별한다.

## 다시 실행

업데이트 후 **setup_windows.bat 한 번 → run_windows.bat**. 이번 새 런타임/모델 추가에만 설치가 필요하며, 이후 실행마다 설치하지 않는다. 연결 문제만 남으면 retry_ocr_windows.bat을 실행한다.

```bash
python -m scripts.check_real_ocr --workers 2
python -m scripts.check_real_ocr --front-only
python -m scripts.check_real_ocr --files 20261029_224822.jpg
```
