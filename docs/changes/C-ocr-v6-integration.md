# OCR 파이프라인6 통합과 실제 CPU 기하 검사

2026-10-31 한국 시간. A826d0bb/ba469e9를 통합하고 C가 검토 상태/캐시 연결과 검사를 보완한다. 공개 recognize_photo/prepare_review/analyze_confirmed와 모델/CSV/enum/CONTRACT_VERSION=1은 유지한다. 새 의존성·모델·외부 사진 전송은 없다. Python3.14 환경과 기존 검증 모델을 재사용한다.

입력: 업로드 사진. 처리: A의 네 방향/약한 방향 재검사, 줄별 곡선과 높이 보정, 문단/단일 행/두 엔진 픽셀 후보 비교. 출력: 같은 미확정 초안 → 최종 사용자 확인 → 같은 분석 결과의 표/그래프/PDF. 실패: 숫자 불일치·기하 추적 실패·모델 실패를 구분하고 기존 성공 경로/원문을 유지한다. C는 자동 제안명을 다시 exact로 바꾸지 않고 원문/후보를 선택하게 한다. 수동 편집은 기존 이름 대조를 사용한다. 사진/입력/후보/DB/파이프라인 변경 때 이전 결과를 지운다.

PIPELINE_VERSION=rows-ensemble-3을 source_key와 모델 캐시 키에 사용한다. 같은 사진의 이전 OCR/PDF와 이전 모델 객체를 재사용하지 않는다. 사용자 사진·원문·선택 결과는 session_state에만 둔다. 선택 영상의 bbox와 image_size를 일치시키고 곡선/줄 배치 메타데이터를 보존한다.

검증: Linux Python3.14에서 전체84개 검사와 서버 검사를 통과했다. 숫자/슬래시/nano 보존, 쉼표-only 줄의 예외, 약한 거짓 heading과180도 재탐색, 짧은 마지막 줄, 위/아래로 서로 다르게 휜 줄, 두 엔진 제안의 미확정 상태, 자동 OCR 상태의 화면 보존과 선택 시 PDF 무효화를 포함한다. 모의 OCR 분기 검사는 사진 정확도와 구분한다.

같은 모델/한 준비 영상의 기본 OCR 결과는 Python3.12.14/3.14.8에서 텍스트 SHA가 같았다. 한 사례의 비교이며 사용자 PC의 모든 차이를 배제하지 않는다. 기존 v5와 같은 Python3.14/DB/모델로 비교한 강한 합성 곡면 입력은 자동 파이프라인의 원문 이름15/26·미확정 제안16/26에서 새 줄별 경로의 원문21/26·제안22/26으로 늘었다. 통합 정방향은 원문21/26을 유지하면서 제안22→24/26이다. 제안 수치를 원문 정확도나 정답 확률로 표시하지 않는다.

scripts.check_ocr_geometry는 원래 인공 전체 라벨의180/90/270도와, 별도 라벨 영역에 원통 압축/줄별 다른 휨/높이 변화·명시적 패딩을 합성한 입력 및 그180도를 실제 CPU로 검사한다. 검사용 영역 선택은 입력을 만드는 과정이며 사이트에 수동 자르기를 요구하는 기능이 아니다. 합성 입력이라는 범위를 결과 JSON에 남긴다. check_windows.bat에도 이5개 검사를 넣었으며 최종 Windows workflow 결과로 별도 확인한다.

제한: 실제 실패 촬영 사진의 원본 파일을 현재 도구로 읽을 수 없어 그 사진을 직접 검증한 것은 아니다. 반사광/흐림으로 사라진 글자를 보장해서 복원하지 않는다. 여러 OCR 경로를 비교하므로 시간이 늘 수 있다. 코드를 갱신한 뒤 앱을 종료하고 run_windows.bat으로 다시 시작한다. 모델이 이미 준비된 사용자는 전체 setup을 다시 실행할 필요가 없다.
