# 유래별 성분 목록과 PDF

2026-10-30 C 웹·통합 변경. A/B의 함수·자료형·유래 분류·분모 계산은 바꾸지 않는다.

## 결과 화면

B의 AnalysisResult.rows를 기존 ORIGINS 순서(석유계 / 식물성 / 기타 / 확인 필요)로 묶고 각 그룹의 제목·개수·표를 처음부터 보여준다. 그룹 내 순서는 입력 순서이며 분류를 다시 계산하지 않는다. 기본 표는 성분·유래·기능 세 열이다. 빈 그룹은 ‘해당 성분 없음’으로 남긴다.

## PDF

입력: 같은 사용자 확정 AnalysisResult → 처리: 내장 Nanum Gothic 글꼴과 벡터 도넛, 자동 페이지 나눔 → 출력: `ingredient-analysis.pdf` → 실패: 화면의 분석은 유지하고 설치/생성 오류를 알린다.

JSON 다운로드를 기본 PDF 다운로드로 교체했다. 그래프, 동일 비율 범례, 유래별 성분표, pH·인체·환경의 평가 한계, 등록된 주의, 출처·확인일을 담는다. 긴 표는 페이지를 나누고 제목 행을 반복한다. 한글 글꼴은 파일에 포함되어 Windows 뷰어의 글꼴 설치에 의존하지 않는다. 글꼴의 OFL과 원본·체크섬은 `ui/assets/fonts/`에 보존한다. 사용자 문자열은 PDF 마크업으로 해석하지 않는다.

PDF 바이트는 사용자 세션 안에서만 재사용한다. 전역 결과 캐시·외부 PDF 서비스·사용자 사진 저장은 사용하지 않는다. 사진·입력·후보 변경으로 결과가 폐기되면 PDF도 폐기된다. 사진·OCR 원문은 PDF에 자동 포함하지 않는다. 시간은 한국 시간으로 표시한다.

## 설치 변경

`reportlab==4.4.4`(PDF 생성), `pypdf==6.1.1`(검사에서 PDF 내용 확인)을 requirements.txt에 추가했다. Windows 기존 사용자도 이번 업데이트 뒤 `setup_windows.bat`을 한 번 실행해야 한다. 기존 .venv와 .cache를 지우지 않는다. 이후에는 run_windows.bat으로 실행한다. 모델이 정상 캐시에 있으면 setup에서 모델을 재사용한다.

## 검증

Linux Python 3.12 CPU에서 전체 pytest 40개, pip check, 서버 검사 통과. PDF에서 한글·특수문자·모든 성분·분모·비율을 추출해 확인하고 긴 90행 자료의 다중 페이지 보존을 검사했다. 생성한 테스트 PDF를 이미지로 렌더링해 제목·도넛·표 배치를 직접 확인했다. Chromium 1280/390px에서 실제 PDF 다운로드, 그룹 헤더, 한글과 평가 한계 문구, 입력 수정 시 PDF/그래프 해제를 확인했다. CPU OCR 인공 라벨 검사는 자동 이름 21/26, 미확정 제안 포함 24/26으로 통과했다. 촬영 사진의 일반 정확도나 실제 Windows 실행을 검증한 결과는 아니다.
