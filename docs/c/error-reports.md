# 오류 제보와 TXT 보관

C 웹·통합 기능. 분석 공통 규격과 A/B 엔진은 변경하지 않는다.

## 사용자 흐름

상단 메뉴의 ‘오류 제보’ → 하단 ‘오류 제보 작성하기’를 펼침 → 유형·제목·오류 내용 입력 → ‘오류 제보 제출’ → TXT 저장 결과 확인과 ‘마지막 제보 TXT 내려받기’.

입력: 사진 인식 / 성분 정보·분석 / 화면·사용 방법 / 기타, 제목(필수 100자), 오류 내용(필수 5,000자).
처리: 빈 내용·길이·NUL 문자를 검사하고, 한국 시간과 임의 접수번호를 붙여 UTF-8 BOM TXT로 만든다.
출력: 실행 컴퓨터의 `reports/errors/error-report-날짜-시각-접수번호.txt`와 동일한 다운로드 파일. Windows 메모장 한글 표시를 위해 BOM을 포함한다.
실패: 저장 권한·공간 등의 문제는 ‘아직 접수되지 않았습니다’로 표시하고, TXT 다운로드와 다시 제출을 제공한다. 같은 세션에서 같은 내용을 다시 제출하거나 페이지가 재실행되어도 성공한 제보를 중복 저장하지 않는다. 다른 내용은 별도 파일이다.

사진·OCR 원문·성분 목록·분석 결과·IP·연락처를 자동으로 포함하지 않는다. 이메일·GitHub·외부 서비스로 보내지 않는다. 다운로드에는 마지막으로 제출한 내용만 담기며 수정 내용은 다시 제출해야 반영된다. 다른 사용자의 제보를 화면에 나열하지 않는다. DB를 읽지 못한 경우에도 제보 폼을 제공한다.

## 운영자 보관 위치

- 기본 위치는 사이트 실행 저장소의 `reports/errors/`이다. `.gitignore`에서 제외해 제보를 Git에 올리지 않는다.
- 선택 환경 변수 `INGREDIENT_REPORT_DIR`에 절대 경로를 지정하면 다른 저장 폴더를 사용할 수 있다. 폴더는 쓰기 가능해야 한다. 비밀키나 새 패키지는 필요 없다.
- 파일명에는 사용자 입력을 사용하지 않고 UUID를 포함한다. 새 파일만 생성하며 기존 제보를 덮어쓰지 않는다. Linux 파일 권한은 0600으로 생성한다. Windows에서는 해당 폴더의 접근 권한을 따른다.
- 운영자가 TXT 파일을 직접 열어 확인하는 방식이다. 관리자 화면·메일 알림·외부 티켓 연동은 구현하지 않았다.
- 공개 배포 시 영구 볼륨을 지정해야 재시작·재배포 이후에도 보존된다. 여러 서버를 운영하면 공유 저장소 구성이 별도로 필요하다. 로컬 폴더만으로 장기 보관을 보장하지 않는다. 필요에 따라 운영자가 백업·보관 기간을 정하고 삭제한다.

## 검사

Linux Python 3.12에서 전체 pytest, 서버, 기존 CPU OCR 연결 검사를 수행한다. 신규 회귀 검사는 동시 파일 생성·한글 인코딩·기존 파일 보존, 빈 제출, 입력만 저장, 중복 제출, 세션 분리, 저장 실패 후 복구, DB 오류 시 폼 접근을 포함한다.
실제 Chromium에서 PC/모바일의 제보 입력·다운로드를 검사하며, 테스트 보고서는 `/tmp`에만 저장한다. 실제 사용자 제보나 촬영 사진을 만들어 제출했다고 주장하지 않는다. Windows 실제 실행과 공개 배포는 별도이다.

이번 실행 결과: 전체 pytest **36개 통과**, 서버 검사 통과, 실제 CPU 인공 라벨 OCR 검사 통과(자동 이름 21/26·미확정 제안 포함 24/26). Chromium 1280px·390px에서 제출·TXT 다운로드·BOM과 서버 파일 일치·중복 방지·가로 넘침 없음까지 확인했다.
