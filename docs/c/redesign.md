접속 범위: Google 검색은 자바스크립트 안내 페이지만 반환해 검색 결과로 사용하지 않았다. Typology·Aesop·INCI Decoder·Yuka 원사이트는 프록시 403으로 열리지 않았다. 해당 사이트를 직접 관찰했다고 주장하지 않는다. 실제로 읽은 GitHub 검색·공개 스크린샷·Radix 화면만 디자인 근거로 삼았다.

## 화면과 흐름

1. 첫 화면: 메뉴, 서비스 설명, 시작 링크, 직접 제작한 용기 일러스트, 세 단계 안내. 시작 링크는 업로드 영역, 이용 안내는 FAQ로 이동한다. 용기 그림은 장식이며 실제 제품·인식 결과가 아니다.
2. 업로드: 흰색 패널에 사진 입력과 촬영 안내를 함께 배치한다. 지원 형식과 앱 제한(10MB/2천만 화소)을 안내한다. 업로드 시 기존 A 파이프라인을 자동 실행한다.
3. 검토: 초기 직접 입력은 접힌 영역으로 제공하며, 사진을 올렸거나 목록이 있으면 펼친다. 자동 보정 사진·원문은 필요한 경우에만 펼친다. 후보 선택과 최종 확인 한 번이라는 기존 흐름을 유지한다.
4. 결과: 같은 B AnalysisResult에서 도넛과 비율 요약을 만든다. 도넛 안에 %와 총 성분 수를 표시한다. 성분 목록·주의 정보·자료 안내를 탭으로 분리하고 중복 비율 표는 제거했다. 기본 표는 성분·유래·기능 세 열이다. 근거·출처·확인일·확인 필요 원인은 자료 안내에 보존한다.
5. 하단: FAQ와 서비스 한계를 설명한다. 분석 기록 다운로드는 계속 제공한다. 제품의 친환경성·안전성을 인증하거나 없는 추천을 표시하지 않는다.

입력 → 처리 → 출력 → 실패: 사진 또는 성분명 → 기존 자동 인식·사용자 최종 확인·분석 → 도넛·요약·표·주의·근거 → 사진 재시도와 직접 입력 경로 유지. 사진·목록·후보 변경 시 이전 결과를 폐기한다.

## 검증

- Linux Python 3.12 CPU: 전체 pytest 32개 통과, 서버 health/HTML 검사 통과.
- 실제 CPU 인공 라벨 검사 통과: 자동 이름 21/26, 미확정 제안 포함 24/26. 실제 촬영 사진의 정확도가 아니다.
- Chromium: 1440/390/320px에서 시작 링크, 직접 입력, 최종 확인, 도넛 화면 범위, 탭 전환, 입력 수정 후 이전 결과 해제를 확인했다. 좁은 화면 가로 넘침과 브라우저 JS 오류를 검사했다.
- 실제 업로드 UI에 손상된 테스트 파일을 넣어 오류 → 재시도 → 직접 입력 복구 → 다른 사진 업로드 시 결과 해제를 검사했다. 테스트용 바이트이며 사용자 촬영 사진은 아니다.
- 실제 Windows 실행과 공개 배포는 수행하지 않았다. Windows 시작 파일과 의존성 선언은 바꾸지 않아 기존 설치 폴더 업데이트 후 앱 재시작으로 사용한다.

외부 폰트·외부 스크립트·원격 이미지를 추가하지 않았다. 그림은 자체 SVG로 제공하고 사용자 사진은 여전히 세션에만 둔다. Streamlit 사용 통계 전송도 끈다. Windows의 시스템 글꼴과 Linux의 글꼴은 다를 수 있다.
